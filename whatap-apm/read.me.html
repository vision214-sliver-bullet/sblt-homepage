WhaTap 수집서버 설치 가이드

멀티모드 9서비스 · air-gap 번들(JRE 동봉) · 버전 gs-3.1.5-6934

이 버전은 범용 배포본이 아닙니다. gs-3.1.5-6934 는 gs 전용 빌드입니다. 다른 환경에 설치하면 그 환경에 없는 기능이 켜지거나 설정이 어긋날 수 있습니다.

담당자에게 대상 버전을 확인한 뒤 진행하세요. 범용 버전은 접두어 없이 2.7.9-5598 같은 형태입니다. 설치된 번들의 정확한 출처는 /data/whatap 전개 시 함께 받은 MANIFEST 의 source·source_sha256 에 기록됩니다.

1. 사전 요구사항

OSLinux + systemd (Ubuntu 20.04+ / RHEL 8+ 등)
RAM16GB 이상 — 9개 JVM heap 합계 약 9.4GB (preflight 기준 14000MB)
디스크yard File DB 용 10GB 이상 여유 (/data/whatap/db)
설치 중 번들 다운로드·전개에 임시로 6GB 추가 필요
JRE번들에 동봉 (Temurin 17.x ≥ 17.0.2) — 호스트에 Java 불필요
포트6500 · 6600 · 6610 · 6620 · 6761 · 6789 · 7700 · 7710 · 7770 · 7800 · 8080 · 8800 · 8870 · 18080 (14종) 미사용
권한설치 시 root (sudo)
라이선스설치 후 whatap-configure 단계에서 입력

2. 설치

A. 권장 — 내려받아 확인한 뒤 실행

설치 스크립트는 root 로 동작합니다. 내용을 먼저 확인하고 실행하세요.

curl -fsSLO https://repo.whatap.io/whatap-installer/install.sh
curl -fsSLO https://repo.whatap.io/whatap-installer/install.sh.sha256
sha256sum -c install.sh.sha256
less install.sh                     # 내용 확인 (q 로 종료)
sudo bash install.sh --version gs-3.1.5-6934

B. 빠른 설치 — 한 줄

curl -fsSL https://repo.whatap.io/whatap-installer/install.sh | sudo bash -s -- --version gs-3.1.5-6934

--version 을 생략하면 접두어 없는 범용(GA) 최신만 선택됩니다. 고객·기능 전용 빌드는 자동으로 선택되지 않습니다 — 아무 옵션 없이 실행한 사람에게 다른 고객용 빌드가 설치되는 것을 막기 위해서입니다.

C. 폐쇄망(air-gap) — 번들을 직접 옮겨 설치

인터넷이 되는 머신에서 3개 파일을 받아 USB·반입 포털로 옮깁니다.

VER=gs-3.1.5-6934
curl -fsSLO "https://repo.whatap.io/whatap-installer/install.sh"
curl -fsSLO "https://repo.whatap.io/tarball/${VER}/whatap-install-airgap-${VER}.tar.gz"
curl -fsSLO "https://repo.whatap.io/tarball/${VER}/whatap-install-airgap-${VER}.tar.gz.sha256"

폐쇄망 노드에서 — --bundle 을 주면 네트워크에 접근하지 않습니다.

VER=gs-3.1.5-6934
sha256sum -c "whatap-install-airgap-${VER}.tar.gz.sha256"
sudo bash install.sh --bundle "whatap-install-airgap-${VER}.tar.gz"

설치 스크립트 옵션

--version <ver>설치할 번들 버전. 생략 시 GA 최신
--bundle <경로>이미 받아 둔 번들로 설치 (폐쇄망 · 네트워크 미사용)
--home <경로>설치 위치 (기본 /data/whatap)
--no-start설치만 하고 기동하지 않음
--list받을 수 있는 버전 목록만 출력
--dry-run내려받기·무결성 검증까지만 (설치하지 않음, root 불필요)

3. 설정 — 설치 직후 반드시 실행

수집서버 IP와 라이선스를 입력하고 기동합니다. 대화형이며, 재실행해도 안전합니다(기존 값이 기본값으로 제시됨).

sudo /data/whatap/bin/whatap-configure

입력 항목: owner IP(이 호스트의 사설 IP — 9개 서비스가 서로를 찾는 주소) · 라이선스 키 · (선택) SMTP. 설정은 /data/whatap/conf/*.conf 에 반영되고 직전 상태는 conf.bak.<타임스탬프> 로 백업됩니다.

4. 확인

systemctl status 'whatap-*.service' --no-pager
systemctl is-active whatap.target
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/

9개 서비스가 모두 active, front 가 200 또는 302 면 정상입니다. 웹 UI 는 http://<호스트IP>:8080 입니다.

초기 계정은 admin@whatap.io / admin 입니다. 첫 로그인 직후 비밀번호를 변경하세요.

기동되지 않을 때

journalctl -u whatap-front -n 100 --no-pager
sudo /data/whatap/bin/preflight.sh          # 포트·메모리·권한 점검
ls -la /data/whatap                          # 홈이 whatap 소유여야 한다

가장 흔한 원인은 포트 충돌과 메모리 부족입니다. 위 preflight 가 둘 다 짚어 줍니다.

5. 업그레이드 · 제거

업그레이드

같은 명령을 새 버전으로 다시 실행합니다. conf 는 보존되고 lib·jre·유닛만 갱신됩니다.

sudo systemctl stop whatap.target
sudo bash install.sh --version <새-버전>
sudo systemctl start whatap.target

제거

기본 제거는 systemd 유닛 9종만 정리하고 데이터와 설정은 보존합니다.

sudo /data/whatap/bin/uninstall.sh

데이터까지 완전히 지우려면 --purge 를 붙입니다.

sudo /data/whatap/bin/uninstall.sh --purge

--purge 는 /data/whatap 전체(yard File DB · 라이선스 · 설정)를 삭제하고 whatap 계정·그룹까지 제거합니다. 되돌릴 수 없습니다 — 필요한 것은 먼저 백업하세요.

폐쇄망에서 번들을 직접 전개해 설치했다면 번들 안 sudo common/uninstall.sh 도 같은 동작을 합니다. 설치 위치를 바꿨다면(--home) 제거 시에도 WHATAP_HOME=<경로> 를 동일하게 지정하세요.

부록 — 받을 수 있는 버전 목록

다운로드 도메인은 CDN 을 거치며 쿼리스트링을 제거하므로, 목록 조회에는 S3 경로 스타일 주소를 씁니다.

curl -sS "https://s3.ap-northeast-2.amazonaws.com/repo.whatap.io/?prefix=tarball/&delimiter=/" \
  | grep -o '<Prefix>tarball/[^<]*/</Prefix>' \
  | sed -E 's#<Prefix>tarball/(.*)/</Prefix>#\1#'

또는 설치 스크립트로:

bash install.sh --list

보관은 최신 20개입니다. 그보다 오래된 버전은 새 버전이 발행될 때 삭제됩니다. 특정 버전을 오래 유지해야 한다면 번들을 내려받아 별도로 보관하세요.
